# Руководство

Здесь собрано то, что нужно для начала: как установить программу, как подключиться к роутеру, что включить на самом роутере и что делать, если не получается. Описаний каждого окна нет. Меню и поля программа читает у роутера, а смысл настроек объясняют производители; для MikroTik это документация RouterOS. О проекте в целом написано в [README.ru.md](README.ru.md).

**English:** [GUIDE.md](GUIDE.md)

## Установка

### Windows

Запустите установщик (`windows-setup.exe`) или переносной файл (`windows-portable.exe`, установки не требует). Если у файла нет подписи издателя, Windows покажет окно «Windows защитила ваш компьютер»: нажмите «Подробнее», затем «Выполнить в любом случае».

Переносной файл при первом запуске распаковывается в `%LOCALAPPDATA%\NetworkHelm\portable\<версия>` (около 200 МБ) и хранит настройки в папке `NetworkHelm data` рядом с собой. Если установщик или переносной файл пишет, что программа не поддерживает эту версию Windows, у вас Windows 7, 8 или 8.1. Для них есть файлы с пометкой `legacy`.

### macOS

Откройте DMG и перетащите NetworkHelm в «Программы». Если программа не подписана Apple, при первом запуске macOS откажется её открыть. Откройте «Системные настройки», «Конфиденциальность и безопасность», найдите сообщение о NetworkHelm и нажмите «Всё равно открыть». Когда macOS спросит про доступ к локальной сети, разрешите его: без этого программа не достанет роутеры вашей сети.

### Linux

DEB и RPM ставятся менеджером пакетов:

```bash
sudo apt install ./NetworkHelm-<версия>-linux-amd64.deb
sudo dnf install ./NetworkHelm-<версия>-linux-x86_64.rpm
```

AppImage не ставится: сделайте файл исполняемым (`chmod +x`) и запустите. Он монтируется через FUSE и ждёт `fusermount` из пакета `fuse3` или `fuse`; без FUSE запускайте его с ключом `--appimage-extract-and-run`.

### Android

Скачайте APK и откройте его, Android спросит разрешение на установку из этого источника. При первом подключении разрешите программе «Устройства поблизости». Без этого Android не пускает её в локальную сеть, и вместо входа вы увидите сообщение «Android не пускает NetworkHelm в локальную сеть».

### iOS

Готового приложения нет, есть проект Xcode. На Mac с Xcode один раз выполните `tools/ios/build-ssh.sh`, затем откройте `app/iosApp` и соберите приложение на своё устройство.

## Первое подключение

При запуске открывается окно подключения. Поля в нём такие:

| Поле | Что вписать |
| --- | --- |
| Адрес | имя или IP-адрес роутера; порт добавляют через двоеточие, если он нестандартный |
| Платформа | тип устройства; программа определяет его сама и пишет рядом «определена сама» |
| Протокол | способ подключения; серым отмечены порты, которые не ответили |
| Порт | менять нужно, только если служба на роутере слушает нестандартный порт |
| Пользователь, Пароль | учётная запись на роутере |
| Запомнить пароль | сохранить пароль в защищённом хранилище системы |
| Группа, Комментарий | для порядка в списке сохранённых роутеров |
| Через роутер | подключиться через SSH другого сохранённого роутера, если нужный недоступен напрямую |

Как только вы вписали адрес, программа почти сразу проверяет, какие порты на роутере отвечают. Она только пробует открыть соединение и читает приветствие, не входя в роутер; по ответам определяет тип устройства и выбирает протокол. Выбор можно поменять руками. У роутера с защитой от подбора паролей такая проверка может сойти за попытку входа, и он заблокирует ваш адрес. Тогда выключите её в «Настройках»: пункт «Распознавать устройство и проверять, какие протоколы отвечают, пока вводится адрес».

Нажмите «Подключиться». Кнопка «Сохранить» кладёт роутер в список на вкладке «Сохранённые», при следующем запуске его достаточно выбрать там. Вкладка «Соседи» показывает MikroTik, которые объявляют себя в вашей сети. Они делают это раз в 30–60 секунд, кнопка «Обновить» просит их ответить сразу.

Если подключение идёт по протоколу без шифрования (API на порту 8728, HTTP, SNMP v2c), под полями появится предупреждение, а в главном окне метка «Без шифрования». Пароль и все данные тогда идут по сети открытым текстом, так что работать в таком режиме стоит только в доверенной сети.

Чтобы открыть конфигурацию без роутера, нажмите «Открыть файл конфигурации» или перетащите файл на окно подключения: подойдёт `/export` RouterOS, бэкап OpenWrt или файл UCI.

## Подготовка роутера

Программа ходит к роутеру через службы, которые на нём уже есть. Если нужная служба выключена или закрыта файрволом, подключиться не получится, и программа напишет, какой порт не отвечает.

### MikroTik RouterOS

Службы видны в WinBox и в консоли: `/ip service print`. Подойдёт любая из них:

| Способ | Порт | Замечания |
| --- | --- | --- |
| WinBox | 8291 | по консоли идёт весь интерфейс, ни API, ни REST, ни SSH не нужны; программа выбирает его первым, если порт отвечает |
| API-SSL | 8729 | шифруется; нужен сертификат: без него RouterOS отвечает анонимным TLS, которым программа не пользуется |
| API | 8728 | без шифрования |
| REST поверх HTTPS и HTTP | 443 и 80 | только RouterOS 7.1 и новее, службы `www-ssl` и `www` |
| MAC-Telnet | UDP 20561 | для роутера без IP-адреса; нужен MAC-адрес и общая сеть второго уровня |

Для нового MikroTik логин обычно `admin`, пароль пустой или напечатан на наклейке. Если у группы пользователя нет прав на какой-то раздел меню, программа помечает его и пишет, каких прав не хватает.

Чтобы перейти на шифрование, сначала подключитесь другим способом. Если с первой попытки вы получили ошибку про TLS (API-SSL включён, а сертификата нет), выберите в списке «Протокол» вариант «API (8728)». Когда соединение откроется, щёлкните по метке «Без шифрования» в главном окне: откроется окно «Подготовить роутер». В нём четыре шага, любой можно отметить или снять, а команды выполнятся по кнопке Apply:

- выпустить самоподписанный сертификат и включить API-SSL (8729);
- разрешить API через туннель SSH (`forwarding-enabled=local`);
- добавить группу пользователей `networkhelm` с правами, которые нужны программе; под неё можно завести отдельного пользователя вместо `admin`;
- выключить открытый API (8728) и Telnet; пока это подключение идёт через API 8728, этот шаг недоступен, иначе оно бы оборвалось.

Дальше подключайтесь по API-SSL: отпечаток сертификата программа спросит один раз.

### OpenWrt

Выберите платформу OpenWrt. Есть два способа:

- SSH, порт 22. Нужен пароль root или ключ. На только что прошитом роутере пароль задают в LuCI, в разделе System, Administration.
- ubus по HTTP (порт 80) или HTTPS (порт 443). Нужны LuCI с модулем ubus у веб-сервера и rpcd; входят под root с его паролем.

Сверху главного окна можно переключать вид меню: «Вид OpenWrt», «Единый вид» (меню, которые у программы есть для любого роутера) и «Вид LuCI».

### OPNsense

На роутере создайте ключ API: System, Access, Users, нужный пользователь, API keys. Скачается файл с ключом и секретом. В программе в поле «Пользователь» впишите ключ, в поле «Пароль» секрет. Порт 443.

### pfSense

Нужен установленный пакет pfSense-pkg-RESTAPI версии 2: без него pfSense не отвечает на API. Войти можно двумя способами: оставить поле «Пользователь» пустым, а в «Пароль» вписать ключ из System, REST API, Keys; либо указать логин и пароль локального пользователя.

### VyOS 1.4 и новее

Нужно включить HTTP API и создать ключ: `set service https api keys id <имя> key <ключ>`, затем `commit` и `save`. В программе поле «Пользователь» оставьте пустым, в «Пароль» впишите ключ. Каждая правка сразу применяется и сохраняется.

### Keenetic и Netcraze

Только чтение. Впишите логин и пароль веб-интерфейса, либо оставьте логин пустым, а в пароль подставьте токен доступа KeeneticOS 5.2 (раздел «Пользователи и доступ»). Эти драйверы написаны по документации, на настоящем устройстве их не пробовали.

### Остальные устройства

Выберите «Другое устройство». Для Linux подойдёт SSH. SNMP v2c читает интерфейсы, адреса и маршруты: в поле «Пароль» вписывают community. Для SNMP v3 нужны имя пользователя и пароли. UPnP и TR-064 находят устройство по порту 1900 (у FRITZ!Box описание на порту 49000). По SNMP, UPnP и TR-064 программа ничего не пишет.

## Безопасность

Если роутер сменил сертификат или ключ SSH, программа сообщит об этом: отпечатки принятых сертификатов и ключей она запоминает. Протоколы без шифрования помечены в окне подключения и в главном окне. В «Настройках» есть пункты «Скрывать пароли и ключи» (в таблицах, диалогах и журнале они будут точками, значение показывает глаз в поле) и «Спрашивать перед удалением с роутера».

### Safe Mode

Safe Mode защищает от правки, после которой роутер перестал отвечать. Как он устроен, зависит от роутера.

На RouterOS нажмите Safe Mode в верхней панели. Пока он включён, при потере связи роутер сам вернёт прежние настройки. Кнопка превращается в меню со счётчиком правок: «Сохранить изменения» оставляет их, «Откатить изменения» отменяет. Если закрыть соединение, не выбрав, программа спросит, оставить ли правки.

На VyOS кнопка включает commit-confirm для каждой правки. Если после правки программа осталась без связи, VyOS примерно через минуту перезагрузится с конфигурацией, сохранённой до неё.

На OpenWrt, OPNsense и pfSense вместо Safe Mode в панели кнопка Apply: она включает сделанные правки в работу. У OpenWrt применение идёт через `uci apply` с откатом, и если после него связь пропала, роутер возвращает прежнюю конфигурацию. У OPNsense 24.7 откатываются правила файрвола, а в API версии 26.7 отката нет. У pfSense отката нет совсем. Где способа отката нет, программа так и пишет.

## Браузерная версия

Браузер не умеет сам открывать соединения с роутерами, поэтому между ним и роутером стоит шлюз. Он хранит сохранённые роутеры и их пароли и подключается к роутерам вместо страницы.

**Из приложения на компьютере.** «Настройки», «Доступ из браузера…». Задайте пароль (вход под именем `admin`), выберите порт и нажмите «Открыть доступ». Окно покажет адреса компьютера и отпечаток сертификата; для телефона есть QR-код. Откройте адрес в браузере телефона или другого компьютера той же сети. Браузер один раз предупредит о самоподписанном сертификате: сверьте его отпечаток SHA-256 с тем, что написано в окне, и продолжайте. Пока доступ открыт, порт виден в заголовке окна, а при следующем запуске приложение откроет его снова. Галочка «Любые адреса, не только локальные сети» нужна для доступа из-за пределов домашней сети (через проброшенный порт или VPN); тогда шлюз каждый раз спрашивает код приложения-аутентификатора (Google Authenticator, Aegis, 2FAS и подобные).

**Отдельным шлюзом.** Архив шлюза (`NetworkHelm-gateway-<версия>-windows-x64.zip` или `-linux-x64.tar.gz`) распаковывается и запускается без установки Java: `networkhelm-gateway.bat` на Windows, `./networkhelm-gateway.sh` на Linux. Пароль первого запуска виден один раз в окне консоли или в журнале. Если вы его потеряли, задайте новый параметром `--reset-password`. Шлюз можно запустить и как jar (нужна Java 17 или новее): `java -jar NetworkHelm-gateway-<версия>.jar`; адрес образа Docker, если он выпущен, указан в описании релиза. Дальше откройте `https://<адрес компьютера>:8443`. По умолчанию шлюз отвечает только локальным сетям; параметр `--public` открывает его для любых адресов и включает обязательный код, `--code` включает код и для локальной сети.

**Прямо на роутере OpenWrt.** Роутер с LuCI может отдавать страницу сам и ходить только к себе через `/ubus`; терминала и файлов в такой странице нет.

Подробнее о шлюзе (все параметры, Docker, контейнер на роутере с RouterOS, служба systemd) в [server/README.ru.md](server/README.ru.md).

**Страница с демонстрацией.** https://vasmarfas.github.io/networkhelm/ показывает интерфейс на вымышленных роутерах. Шлюза у неё нет, а страница в браузере умеет только HTTP, так что до большинства настоящих роутеров она не дотянется. Как устроена такая страница и что она умеет, написано в [app/webApp/README.ru.md](app/webApp/README.ru.md).

## Если что-то не получается

| Что вы видите | В чём дело | Что делать |
| --- | --- | --- |
| «… не принимает подключения на порт N: сервис выключен или порт закрыт» | служба на роутере выключена или порт закрыт файрволом | включите службу (на RouterOS, например, `/ip service enable api`) или выберите другой протокол; серым в списке помечены порты, которые не ответили |
| «… не отвечает» | неверный адрес, нет маршрута или файрвол молча отбрасывает пакеты | проверьте адрес, пропингуйте роутер, убедитесь, что вы в той же сети; если роутер за другим роутером, используйте поле «Через роутер» |
| «… не найден» | имя не удаётся преобразовать в адрес | впишите IP-адрес |
| «Роутер не принял вход: …» | неверный логин или пароль, либо у пользователя нет прав на эту службу | проверьте их и, на RouterOS, группу пользователя |
| «… и NetworkHelm не договорились о TLS …» | на RouterOS включён API-SSL, но у службы нет сертификата | выберите «API (8728)», подключитесь и в окне «Подготовить роутер» выпустите сертификат |
| «Android не пускает NetworkHelm в локальную сеть» | не выдано разрешение | в настройках приложения Android разрешите «Устройства поблизости» |
| «Соединение оборвалось после отправки команды …» | связь пропала в момент правки | сначала проверьте роутер: команда могла выполниться, и повтор сделает её дважды |
| Роутер перестал отвечать сразу после ввода адреса | его защита от подбора паролей сочла проверку портов попыткой входа | дождитесь конца блокировки и выключите проверку в «Настройках» |
| «Браузер заблокировал запрос …» | страница в браузере умеет только HTTP | откройте приложение через шлюз |
| Программа не запускается | на компьютере причина записана в файл `NetworkHelm-startup-error.log` во временной папке | возьмите файл (`%TEMP%` в Windows, `/tmp` в Linux) и приложите к обращению вместе с версией системы |

Остальное можно спросить в [трекере задач](https://github.com/vasmarfas/networkhelm/issues). Адреса, пароли и ключи в обращения не вставляйте.

## Где лежат данные

Сохранённые роутеры, настройки и раскладки таблиц программа хранит в своей папке данных. Пароли и ключи, которые вы попросили запомнить, лежат в защищённом хранилище системы: защита данных Windows (DPAPI), связка ключей в macOS и iOS, Secret Service в Linux, Android Keystore в Android. Если системного хранилища нет, программа шифрует их сама, и такая защита слабее. Всё подробно описано в [privacy-policy.md](privacy-policy.md).
